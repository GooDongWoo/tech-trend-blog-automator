## 구현한 흐름

`원문 스냅샷 → 근거 패킷 → 편집 브리프 → 주장 연결표가 있는 초안 → 검증·제한된 수정 → 전체 검토 → 승인 → 명시적 발행 → push 확인 → Vault 동기화`

- HTML·README·PDF의 원문 바이트, 추출 텍스트, 위치와 해시를 보존한다. 실패는 `NEEDS_RESEARCH`로 남긴다.
- 브리프에 작동 원리, 대안, 선택 기준, 제약과 판단을 뒤집을 조건을 요구한다. 사용자 목표·제약·명시적 실행 로그는 선택한 주제와 함께 저장하고 재시작·재시도에 동일하게 사용한다.
- 수치는 원저자의 주장으로 남기고 값·단위·대상·baseline·조건을 검사한다. 자동 메타데이터 준비는 명시적인 원문 표현만 처리하며 서로 다른 실험의 조건을 가져오지 않는다. 일반적인 표 해석이나 연구 타당성 검증까지 수행하는 것은 아니다.
- 생성과 수정에 실제로 적용되는 근거 문맥을 제한한다. 전체 원문은 로컬에 남기고 근거 ID는 재번호하지 않는다. 필수 문맥이 예산을 넘으면 모델 호출을 차단한다.
- 유지보수 규칙은 [AGENTS.md](../AGENTS.md), 실행 프롬프트의 규칙은 [policy.md](../src/editorial/policy.md)에 둔다. 가짜 경험, 출처 없는 성능 수치, 성공처럼 보이는 실패 대체 글을 허용하지 않는다.
- 밈은 0–1개를 선택한다. 등록된 장면·alt·사용 조건과 실제 바이트를 검사한다. 기존 GIF 8개는 사용 조건이 확인되지 않아 제외 상태다.
- Telegram은 전체 초안과 근거·검증·주장 연결표를 전달한다. 승인과 발행은 특정 초안 ID, 해시, 검토자에 묶인다.
- 발행은 검토된 입력·본문·미디어를 재검증하고 해당 파일만 커밋한다. 실제 push 대상을 고정하며 불확실한 push는 원격 확인 전 재시도하지 않는다. Vault 동기화 실패는 발행 성공과 별도로 보존하고 push 없이 재시도한다.
- Telegram 기본값은 shadow다. 품질 게이트와 별도 운영 전환 설정 없이는 발행하지 않는다.
